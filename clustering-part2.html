🧩 Как именно модель делится между устройствами

Это фундаментально важно понять, потому что от выбора метода зависит, будет ли кластер работать быстро или «для галочки».

Pipeline Parallel (послойное)

Устройство A Устройство B Устройство C ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ Слои 1–20 │ ──► │ Слои 21–40 │ ──► │ Слои 41–60 │ │ │ │ │ │ │ │ Обработал │ │ Жду данные │ │ Жду данные │ │ свою часть │ │ от A... │ │ от B... │ └─────────────┘ └─────────────┘ └─────────────┘ Каждый токен проходит ВСЕ устройства последовательно. Пока B работает, A и C простаивают. ✅ Плюсы: Простая реализация, минимум данных между узлами ❌ Минусы: Чем больше узлов, тем БОЛЬШЕ простоя → замедление! 📌 Используют: llama.cpp RPC, distributed-llama

Tensor Parallel (тензорное)

Один слой модели ┌──────────────────────────────────┐ │ Матрица весов 8192×8192 │ │ │ │ Разрезаем по столбцам: │ │ │ │ A получает B получает │ │ столбцы 1-4096 столбцы 4097-8192│ └──────────────────────────────────┘ Устройство A Устройство B ┌──────────────┐ ┌──────────────┐ │ Половина │ ◄──────► │ Половина │ │ каждого слоя │ RDMA! │ каждого слоя │ │ │ постоянно│ │ │ Работает │ обмен │ Работает │ │ ОДНОВРЕМЕННО │ │ ОДНОВРЕМЕННО │ └──────────────┘ └──────────────┘ Оба устройства работают ПАРАЛЛЕЛЬНО на каждом токене. Но нужен ОЧЕНЬ быстрый канал (RDMA, NVLink). ✅ Плюсы: Линейное ускорение! 2 узла ≈ 2× быстрее ❌ Минусы: Требует огромный bandwidth между узлами 📌 Используют: EXO 1.0 (TB5 RDMA), vLLM, NVLink-кластеры

Disaggregated (разделение фаз)

Запрос пользователя │ ▼ ┌─────────────────────────┐ │ PREFILL фаза │ ← Compute-bound (нужен GPU) │ Обработка всего │ │ промпта сразу │ Выполняет: NVIDIA DGX Spark │ (параллельно) │ или RTX GPU └───────────┬─────────────┘ │ KV-cache передаётся ▼ ┌─────────────────────────┐ │ DECODE фаза │ ← Bandwidth-bound (нужна память) │ Генерация токенов │ │ по одному │ Выполняет: Mac Studio / Mac Mini │ (последовательно) │ (много памяти, хороший bandwidth) └─────────────────────────┘ ✅ Плюсы: Каждое устройство делает то, в чём оно лучше! ❌ Минусы: Сложная оркестрация, нужна быстрая передача KV-cache 📌 Используют: EXO 1.0 (гибрид NVIDIA + Apple) 📌 Это БУДУЩЕЕ inference на гетерогенном железе

Сравнительная таблица

Метод Скорость при 2 узлах Скорость при 4 узлах Мин. bandwidth Софт
Pipeline Parallel ~0.9× (медленнее 1 узла!) ~0.7× (ещё медленнее) 1 Гбит/с+ llama.cpp RPC, dllama
Tensor Parallel ~1.7× (почти 2× ускорение) ~3.2× (близко к линейному) 40 Гбит/с+ (RDMA) EXO 1.0, vLLM, MLX Distributed
Disaggregated ~2.8× (EXO бенчмарк) Зависит от конфигурации 10 Гбит/с+ EXO 1.0, NVIDIA Dynamo
Критический вывод: Pipeline parallel по обычному Ethernet — это самый доступный, но и самый медленный метод. Добавление узлов часто замедляет inference. Tensor parallel с RDMA — кардинально быстрее, но требует Thunderbolt 5 (Apple) или NVLink/InfiniBand (серверы). Для мини-ПК на Ethernet кластеризация имеет смысл только для загрузки моделей, которые не влезают в один узел.

DGX Spark vs Mac Mini для кластеров:
• DGX Spark: 128 ГБ в 1 устройстве за $4 000, CUDA, но макс. 2 узла, 273 ГБ/с bandwidth
• 4× Mac Mini M4 Pro 64 ГБ: 256 ГБ за $8 800, без CUDA, но 4+ узла, TB5 RDMA
• Mac Studio M3 Ultra 512 ГБ: 512 ГБ за $9 000, 819 ГБ/с bandwidth — самый быстрый decode
• Гибрид EXO: 2× DGX Spark (prefill) + Mac Studio (decode) = лучший из обоих миров

🔮 CXL — будущее «объединённой памяти» для PC

Compute Express Link (CXL) — это стандарт, который потенциально решает главную проблему PC: невозможность объединить память нескольких устройств. CXL работает поверх физического уровня PCIe и добавляет cache-coherent доступ к удалённой памяти.

Эволюция CXL

Версия На базе Что добавляет Bandwidth Статус
CXL 1.0/1.1 PCIe 5.0 CPU может читать память внешних устройств (GPU, FPGA) ~64 ГБ/с (x16) Доступен
CXL 2.0 PCIe 5.0 Memory pooling: несколько хостов делят пул памяти через свитч ~64 ГБ/с (x16) Серверы 2025–26
CXL 3.0/3.1 PCIe 6.0 Multi-level switching, fabric, до 4096 устройств в пуле ~128 ГБ/с (x16) Продакшн 2027
CXL 4.0 PCIe 7.0 Multi-rack fabric, bundled ports, retimers для дальних расстояний ~768 ГБ/с (x16 bundled) Спецификация ноя. 2025, железо ~2028

Горькая правда: CXL в потребительских ПК и мини-ПК — это НЕ скоро. Текущие десктопные платформы Intel и AMD не поддерживают CXL. Даже серверные CXL 2.0 решения стоят тысячи долларов за свитч + модули памяти. Для домашнего использования Apple RDMA через Thunderbolt 5 остаётся единственным реальным вариантом объединения памяти в 2025–2027.

🔧 Мини-ПК с unified memory: почему это НЕ то же, что Apple

Мини-ПК на AMD Ryzen AI / Intel Core Ultra действительно имеют «общую» память (DDR5 shared между CPU и iGPU). Но это принципиально отличается от Apple.

Apple UMA

Память: LPDDR5/5x

Распаяна на SoC (System-on-Chip)

Bandwidth:

M4 Pro: 273 ГБ/с, M3 Ultra: 819 ГБ/с

Весь пул доступен GPU на полной скорости

GPU использует ту же физическую память, что и CPU — никаких копирований

AMD/Intel мини-ПК

Память: DDR5 SO-DIMM

Вставляется в слоты на материнской плате

Bandwidth:

Dual-channel DDR5: 50–90 ГБ/с

iGPU получает часть этого bandwidth

iGPU «ворует» часть RAM у CPU, контроллер памяти — общее узкое место
