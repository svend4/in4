Ключевые архитектурные отличия SBC от мини-ПК и Mac

Bandwidth памяти — главное ограничение SBC. Raspberry Pi 5 даёт ~34 ГБ/с (LPDDR4X). Orange Pi 5 на RK3588 — ~51 ГБ/с. Для сравнения: Mac Mini M4 Pro — 273 ГБ/с, Strix Halo — 256 ГБ/с. Разница в 5–8× определяет скорость LLM-инференса напрямую, поскольку генерация токенов — операция, ограниченная bandwidth памяти.

RAM — потолок в 8–16 ГБ (Pi 5) или 32 ГБ (RK3588). Для моделей 70B+ в Q4-квантизации нужно ~40 ГБ, поэтому без кластера не обойтись. Но именно при кластеризации начинаются проблемы с сетевой латентностью.

NPU (Neural Processing Unit) — RK3588 имеет встроенный NPU на 6 TOPS, а новый Raspberry Pi AI HAT+ 2 (январь 2026) добавляет 40 TOPS через модуль Hailo-10H с 8 ГБ собственной RAM. Это интересно для мелких моделей (1–7B), но не решает проблему крупных.

2. 📊 Бенчмарки LLM на одном узле SBC

Raspberry Pi 5 (8 ГБ)

Научная работа arXiv (октябрь 2025) протестировала 25 квантизированных LLM на трёх SBC. Основные результаты:

Модель Параметры Pi 5 (8 ГБ), tok/s Orange Pi 5 Pro (RK3588), tok/s Pi 4 (4 ГБ), tok/s
gemma3:1b 1B 15–20+ 20+ 5–8
Qwen2.5:1.5b 1.5B 10–15 15+ 4–6
BitNet B1.58 2B 4T 2B ~8 (bitnet.cpp) — —
Llama 3.2:3b 3B 4–6 3–5 1–2

Llamafile vs Ollama: Исследование показало, что Llamafile в 4× быстрее Ollama и потребляет на 30–40% меньше энергии на тех же SBC. Ollama не оптимизирован для устройств с ограниченными ресурсами — по умолчанию выделяет контекст 4096 токенов и использует все 4 ядра без возможности лёгкой настройки. llama.cpp напрямую — на 10–20% быстрее Ollama и даёт полный контроль над параметрами.

RK3588 NPU — отдельная история

На Orange Pi 5 с RK3588 NPU (через RKLLM runtime): TinyLlama 1.1B достигает 10–15 tok/s на NPU при потреблении всего 5–6 Вт. Это быстрее, чем человек может читать, и отлично для edge-задач. Но: NPU поддерживает только W8A8 квантизацию, закрытый toolchain от Rockchip, ограниченный набор моделей. Проект RKLLama (аналог Ollama для NPU RK3588) активно развивается и уже поддерживает tool calling и TTS.

Raspberry Pi AI HAT+ 2 (январь 2026)

Новый модуль Hailo-10H: 40 TOPS (INT4) + 8 ГБ собственной DDR4 RAM, подключается через PCIe Pi 5. Предназначен для LLM до 7B параметров, VLM и компьютерного зрения. Стоимость ~$70–100. Пассивное охлаждение (нагревается). Ещё очень свежий продукт — экосистема софта формируется.

Практический вывод по одному узлу: На Raspberry Pi 5 (8 ГБ) модели 1–3B работают на 5–15 tok/s — вполне юзабельно для чатботов. Модели 7–8B — на 1–3 tok/s — медленно, но работает. Orange Pi 5 Pro (RK3588, 16 ГБ) даёт небольшое преимущество за счёт 8 ядер и NPU, особенно для моделей до 3B. Модели 70B+ невозможны на одном SBC — нужен кластер.

3. 🔗 Бенчмарки кластеров SBC: реальные цифры

distributed-llama (автор: b4rtaz) — единственный фреймворк, показывающий положительное масштабирование на Raspberry Pi кластерах. Использует тензорный параллелизм через TCP (не pipeline, как llama.cpp RPC).

Qwen3-30B-A3B — звезда SBC-кластеров! Это MoE-модель с 30B общих параметров, но только 3B активных на токен. На 4× Pi 5 она даёт 13 tok/s — это быстрее разговорной речи. Общий вес ~5.5 ГБ (Q40), легко помещается в кластер из четырёх Pi 5 по 8 ГБ. Это лучшее соотношение качество/скорость для SBC-кластера на сегодня.

distributed-llama: пошаговая настройка на 4× Pi 5

Топология:

[🔀 TP-Link LS1008G Switch (Gigabit)] | | | | |_______ 🔸 Pi 5 #1 (ROOT) 10.0.0.1 | | |_______ 🔹 Pi 5 #2 (WORKER) 10.0.0.2:9999 | | |_______ 🔹 Pi 5 #3 (WORKER) 10.0.0.3:9999 | |_______ 🔹 Pi 5 #4 (WORKER) 10.0.0.4:9999

Установка:

# На каждом Pi 5: git clone https://github.com/b4rtaz/distributed-llama.git cd distributed-llama make # Скачать модель (на root-узле): python launch.py qwen3_30b_a3b_q40 # Запуск worker'ов (на каждом worker Pi): ./dllama worker --port 9999 --nthreads 4 # Запуск инференса (на root-узле): ./dllama inference \ --model models/qwen3_30b_a3b_q40/dllama_model_qwen3_30b_a3b_q40.m \ --tokenizer models/qwen3_30b_a3b_q40/dllama_tokenizer_qwen3_30b_a3b_q40.t \ --buffer-float-type q80 \ --nthreads 4 \ --max-seq-len 4096 \ --workers 10.0.0.2:9999 10.0.0.3:9999 10.0.0.4:9999 \ --prompt "Hello, explain quantum computing" \ --steps 128
Ограничения distributed-llama: Работает только на 1, 2, 4, 8... 2^n узлах. Максимальное число узлов = числу KV-голов в модели. Поддерживаются только определённые квантизации. Vulkan-поддержка для MoE-моделей добавлена недавно. Количество потоков (nthreads) не должно превышать число ядер CPU.

5. 🌐 Сеть и интерконнекты для SBC-кластеров

Интерконнект Bandwidth Латентность RDMA? Доступность на SBC Стоимость
Gigabit Ethernet 1 Гбит/с (125 МБ/с) ~300–500 мкс ❌ Все Pi 5, все RK3588 Свитч $15–30
2.5 GbE 2.5 Гбит/с (312 МБ/с) ~200–400 мкс ❌ Orange Pi 5 Plus (встроен), Rock 5B (через M.2) Свитч $30–60
USB Ethernet адаптер (2.5G) 2.5 Гбит/с ~300–500 мкс ❌ Pi 5 через USB3 Адаптер $12–20
PoE (Power over Ethernet) 1 Гбит/с ~300 мкс ❌ Pi 5 с PoE HAT HAT $12 + PoE свитч $50–80
ClusterHAT (USB gadget) ~100 Мбит/с ~500+ мкс ❌ Pi Zero только HAT ~$25
Главное ограничение: Все SBC-кластеры работают через TCP поверх Gigabit Ethernet. Нет ни одного SBC с поддержкой RDMA, Thunderbolt 5, или InfiniBand. Это значит латентность 300+ мкс на каждую синхронизацию — на порядки хуже, чем 3 мкс у Apple TB5 RDMA. distributed-llama смягчает это, используя оптимизированные TCP-сокеты и буферизацию q80, но фундаментальное ограничение остаётся.

Оптимальная сетевая конфигурация для SBC-кластера

Минимум: Гигабитный неуправляемый свитч (TP-Link LS1008G, ~$20) + Cat5e/Cat6 кабели. Это работает и проверено.

Оптимально: 2.5 GbE свитч + SBC с 2.5G портами (Orange Pi 5 Plus). 2.5× больше bandwidth = меньше времени на синхронизацию между узлами.

PoE: Для чистоты проводки — PoE HAT на Pi 5 + PoE свитч. Один кабель = питание + сеть. Но PoE свитчи дороже ($50–80 за 8 портов).

Почему Orange Pi 5 Plus — лучший SBC для кластера

Единственный SBC из доступных с двумя портами 2.5 GbE (Realtek RTL8125). Это позволяет:

Один порт — внутренний кластерный трафик. Второй порт — внешняя связь с интернетом/LAN. Без необходимости в USB-адаптерах или WiFi. Плюс 8 ядер RK3588 (vs 4 у Pi 5) и до 32 ГБ RAM (vs 16 у Pi 5).

• Единственное преимущество Pi-кластера: MoE-модели (Qwen3-30B-A3B) при 13 tok/s на $585 — неплохо для бюджета.

Когда SBC-кластер имеет смысл

✅ Образование и обучение: Построить кластер — отличный способ изучить распределённые вычисления, Linux, сети, MPI, и AI. Raspberry Pi имеет гигантское сообщество и документацию.

✅ MoE-модели на бюджете: Qwen3-30B-A3B на 4× Pi 5 за $585 = 13 tok/s. Это реально полезная скорость для чатбота. Лучшее соотношение цена/качество для offline AI на бюджете.

✅ Edge AI / IoT: Десяток Pi с мелкими моделями (1–3B) — для умного дома, видеонаблюдения, голосовых ассистентов. Каждый узел обрабатывает свою задачу.

✅ Homelab / Kubernetes: Pi-кластеры отлично подходят для изучения K8s, Docker Swarm, MicroK8s. Это их основной use case.

✅ Низкое энергопотребление: 4× Pi 5 = ~40 Вт. Работает тихо, можно оставлять включённым 24/7.
❌ Когда SBC-кластер НЕ имеет смысла:

Для быстрого инференса больших моделей: Один Mac Mini M4 Pro или Framework Desktop бьёт любой Pi-кластер по скорости tok/s на доллар.

Для моделей 70B+: 0.28–0.85 tok/s — непрактично. Один ответ на промпт занимает минуты.

Для продакшн-использования: distributed-llama иногда выдаёт мусор. llama.cpp RPC замедляется с узлами. Стабильность не гарантирована.

По соотношению цена/производительность: С учётом кризиса цен на RAM в 2026 (Pi 5 16 ГБ = $205), б/у мини-ПК x86 (Dell OptiPlex, HP ProDesk, $50–100 с 16 ГБ DDR4) часто выгоднее.

8. 🤖 Для агентов с облачным API — совсем другая математика

Если AI-агент (типа Moltbot) использует облачные API (Claude, GPT, DeepSeek), то всё вышеизложенное про bandwidth, кластеры и tok/s — не имеет значения. Сервер агента — просто «диспетчер»: принимает задачу, формирует промпт, отправляет в API, получает ответ, автоматизирует действия.

Для этого нужен: стабильный интернет, Python/Node.js, 2–4 ГБ RAM, надёжная работа 24/7. Любой из этих вариантов справится одинаково:

9. 🎯 Итоговый вердикт

Для локального LLM-инференса

SBC-кластеры имеют нишу, но она узкая.

Единственная конфигурация, которая действительно работает хорошо: 4× Raspberry Pi 5 (8 ГБ) + distributed-llama + MoE-модель (Qwen3-30B-A3B) за ~$585 → 13 tok/s. Это приемлемая скорость для чатбота при минимальном бюджете.

Для всего остального — моделей 70B+, быстрого инференса, стабильности — один мини-ПК за те же деньги побеждает.

Финальная мысль: SBC-кластеры — это прежде всего образовательный проект и хобби. Они учат распределённым вычислениям, Linux-администрированию, сетям, и AI на edge. Для практического AI-инференса — один мощный узел (Mac Mini, Framework Desktop, или даже б/у серверный ПК) всегда побеждает кластер из маленьких плат. Для облачных агентов — самое дешёвое стабильное устройство с интернетом.
Данные актуальны на февраль 2026. Цены могут отличаться из-за кризиса RAM.
