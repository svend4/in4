Почему 2 узла для старта? 2× Mac Mini M4 Pro 24 ГБ = 48 ГБ общей памяти. Этого хватит для Llama 30B (Q4), Qwen 32B (Q4), и многих других моделей, которые не помещаются в один Mac. При расширении добавляете 3-й и 4-й Mac Mini — кабели TB5 и EXO автоматически подхватит.

Пошаговая настройка

1 Обновите macOS до Tahoe 26.2+

System Settings → General → Software Update. RDMA доступен только с 26.2.

2 Включите RDMA (на КАЖДОМ Mac'е)
# Выключите Mac # Зажмите кнопку питания на 10 секунд → появится меню загрузки # Выберите "Options" → Recovery Mode # В Recovery: Utilities → Terminal rdma_ctl enable # Перезагрузите Mac
3 Соедините Mac'и кабелем Thunderbolt 5
Mac Mini A ──── TB5 кабель ──── Mac Mini B ⚠️ На Mac Studio: НЕ используйте TB5 порт рядом с Ethernet! Используйте любой из остальных 4 портов. Для 4 узлов — полная mesh-сеть (каждый к каждому): Mac A ─── Mac B │ \ / │ │ \/ │ │ /\ │ │ / \ │ Mac C ─── Mac D (6 кабелей для full-mesh, или daisy-chain с меньшим числом)
4 Установите EXO (на КАЖДОМ Mac'е)
# Установите Homebrew (если нет) /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)" # Установите зависимости brew install python@3.12 node git # Установите uv (менеджер пакетов Python) curl -LsSf https://astral.sh/uv/install.sh | sh # Клонируйте EXO git clone https://github.com/exo-explore/exo.git cd exo # Соберите dashboard cd dashboard && npm install && npm run build && cd .. # Настройте RDMA сеть (отключает TB Bridge, включает DHCP на RDMA портах) bash tmp/set_rdma_network_config.sh
5 Запустите EXO (на КАЖДОМ Mac'е)
uv run exo # EXO автоматически обнаружит другие устройства! # Dashboard доступен по адресу: http://localhost:52415
6 Запустите модель через API
# Посмотрите, какие модели можно запустить на вашем кластере: curl "http://localhost:52415/instance/previews?model_id=llama-3.2-1b" # Создайте инстанс модели (EXO сам распределит по узлам): curl -X POST http://localhost:52415/instance \ -H 'Content-Type: application/json' \ -d '{"model_id": "mlx-community/Llama-3.2-1B-Instruct-4bit"}' # Отправьте запрос: curl -N -X POST http://localhost:52415/v1/chat/completions \ -H 'Content-Type: application/json' \ -d '{ "model": "mlx-community/Llama-3.2-1B-Instruct-4bit", "messages": [{"role": "user", "content": "Привет!"}] }'
Готово! EXO предоставляет OpenAI-совместимый API. Вы можете подключить к нему любой клиент: Open WebUI, Continue (VS Code), SillyTavern, или свой Moltbot-агент.

Пошаговая настройка

1 Установите Linux на все узлы
# Ubuntu 24.04 Server рекомендуется # Установите SSH для удалённого управления sudo apt update && sudo apt install -y openssh-server
2 Установите llama.cpp на ВСЕХ узлах
sudo apt install -y build-essential cmake git git clone https://github.com/ggml-org/llama.cpp.git cd llama.cpp cmake -B build cmake --build build --config Release -j$(nproc)
3 Запустите RPC-серверы на воркерах (узлы B, C)
# На узле B (IP: 192.168.1.102): ./build/bin/llama-rpc-server --host 0.0.0.0 --port 50052 --mem 28000 # На узле C (IP: 192.168.1.103): ./build/bin/llama-rpc-server --host 0.0.0.0 --port 50052 --mem 28000 # --mem указывает сколько МБ RAM отдать под модель
4 Запустите мастер-узел (узел A) с подключением к воркерам
# Скачайте модель (только на мастере — он раздаст слои воркерам): wget https://huggingface.co/bartowski/Llama-3.1-70B-Instruct-GGUF/resolve/main/Llama-3.1-70B-Instruct-Q4_K_M.gguf # Запустите с RPC-воркерами: ./build/bin/llama-server \ -m Llama-3.1-70B-Instruct-Q4_K_M.gguf \ --rpc 192.168.1.102:50052,192.168.1.103:50052 \ --host 0.0.0.0 --port 8080 \ -c 4096 -ngl 0 # llama.cpp автоматически распределит слои по узлам # API доступен на http://192.168.1.101:8080
Ожидайте: На 3× Beelink с Ethernet 2.5G, Llama 70B Q4 будет выдавать ~1–2 tok/s. Это работает, но мучительно медленно. Для комфортной работы (10+ tok/s на 70B) нужен Mac-кластер с RDMA или один Mac Studio Ultra.

Когда локальный кластер выгоднее облака?
• При использовании дорогих API (Claude, GPT-4o) → окупается за 7–10 месяцев
• При большом объёме (>3M токенов/день) → однозначно выгоднее
• При требованиях к приватности → бесценно
• При использовании дешёвых API (DeepSeek, Together.ai) → облако выгоднее 3–9 лет
• Вывод: Для Moltbot-агента с облачным API — Mac Mini за $599 как сервер + облачный API = оптимально. Кластер для LLM — если хотите полный оффлайн и большие модели.

🔧 Частые проблемы и решения

Проблема Причина Решение
EXO не видит другие Mac'и Thunderbolt Bridge включён Запустите bash tmp/set_rdma_network_config.sh — он отключит TB Bridge и настроит DHCP
RDMA не работает Не включён в Recovery Перезагрузите в Recovery и выполните rdma_ctl enable. Проверьте macOS ≥ 26.2
TB5 порт не определяется как RDMA На Mac Studio: порт рядом с Ethernet не работает для RDMA Используйте любой другой TB5 порт
Кабель TB5 не работает Пассивный кабель или USB-C вместо TB5 Используйте сертифицированный активный Thunderbolt 5 кабель
Модель не загружается (OOM) Недостаточно памяти в кластере Используйте более агрессивную квантизацию (Q4 → Q2_K) или добавьте узлы
llama.cpp RPC — медленно на 4 узлах Pipeline parallel: больше узлов = больше простоев Нормальное поведение. Переходите на EXO + RDMA или используйте только 2 узла
PC кластер: ROCm ошибки AMD драйвера нестабильны для AI Используйте Vulkan backend или CPU. ROCm для consumer GPU = лотерея
EXO на Linux — нет GPU Linux поддержка = CPU-only (пока) Используйте llama.cpp RPC для Linux. EXO GPU — только на Mac (MLX)
Высокая латентность между узлами Ethernet 1G / Wi-Fi Минимум Ethernet 2.5G. Для серьёзных задач — 10G или Thunderbolt
Модель генерирует мусор Баг в distributed-llama / Vulkan Попробуйте другой backend (CPU вместо Vulkan) или другую версию софта

🌐 Оптимизация сети для AI кластеров

Иерархия скорости соединений

🏆 TB5 RDMA (10 ГБ/с, 3 мкс) │ ├── Для Apple кластеров: ЕДИНСТВЕННЫЙ выбор для tensor parallel │ Настройка: rdma_ctl enable + TB5 кабель │ 🥈 Ethernet 10G (1.25 ГБ/с, ~100 мкс) │ ├── Для PC кластеров: хороший вариант │ Свитч ~$150, SFP+ карты ~$30/шт │ С jumbo frames (MTU 9000) → до 15% ускорение │ 🥉 Ethernet 5G (625 МБ/с, ~150 мкс) │ ├── Framework Desktop имеет 5G встроенный │ Свитч NICGIGA 5G ~$80 │ 😐 Ethernet 2.5G (312 МБ/с, ~200 мкс) │ ├── Большинство мини-ПК. Минимум для кластера. │ Свитч ~$40 │ 😞 Ethernet 1G (125 МБ/с, ~500 мкс) │ └── Слишком медленно для AI. Не используйте.

Таблица решений

Вопрос → Ответ
У меня $700, хочу начать с AI → 1× Mac Mini M4 24 ГБ ($699). Не кластер — один сервер. 7–13B моделей хватит.
У меня $3 000, хочу 70B модель → 2× Mac Mini M4 Pro 24 ГБ ($2 800) + TB5 RDMA + EXO. 48 ГБ = Llama 70B Q2_K.
У меня $6 000, хочу 70B модель комфортно → 2× Mac Mini M4 Pro 48 ГБ ($3 600) или 1× Mac Mini M4 Pro 64 ГБ + 1× Mac Mini M4 Pro 48 ГБ. 96–112 ГБ = Llama 70B Q6 с запасом.
У меня $9 000, хочу DeepSeek 671B → 4× Mac Mini M4 Pro 64 ГБ ($8 800). 256 ГБ = DeepSeek V3 Q4.
Мне нужна CUDA совместимость → DGX Spark ($4 000). Или PC с RTX 4090 ($2 500) для 7–32B моделей.
У меня есть мини-ПК, хочу кластер → llama.cpp RPC через Ethernet. Работает, но медленно. Для экспериментов ОК.
Можно ли смешивать Mac и PC? → Да! EXO поддерживает гетерогенные кластеры (Mac MLX + Linux tinygrad). Но RDMA только между Mac'ами.
Стоит ли ждать CXL для PC? → Нет. В десктопных CPU не раньше 2027–28. Покупайте то, что работает сейчас.
Мне нужен AI-агент (Moltbot), не LLM → 1× Mac Mini M4 16 ГБ ($599) + облачный API. Кластер не нужен.
Что лучше: кластер дешёвых Mac Mini или один Mac Studio Ultra? → Кластер: больше памяти, дешевле. Studio: быстрее (819 ГБ/с bandwidth), проще. Для 70B → Studio. Для 671B → кластер.
