1. Введение: зачем Vulkan для prima.cpp

Prima.cpp — это распределённая система инференса LLM, построенная поверх llama.cpp. Она позволяет запускать модели масштаба 70B на домашнем кластере из обычных устройств: ноутбуки, десктопы, телефоны.

Проблема: prima.cpp поддерживает GPU-ускорение только через CUDA (NVIDIA) и Metal (Apple). Это означает:

GPUТекущая поддержкаПосле Vulkan-порта
NVIDIA GeForce/RTX✅ CUDA✅ CUDA + Vulkan
NVIDIA Tesla/Datacenter✅ CUDA✅ CUDA + Vulkan
Apple M1/M2/M3/M4✅ Metal✅ Metal (+ MoltenVK)
AMD Radeon RX 6000/7000/9000❌ Нет✅ Vulkan
Intel Arc A770/A750/A580❌ Нет✅ Vulkan
ARM Mali G610/G710/G720❌ Нет✅ Vulkan
Qualcomm Adreno 730/740/750❌ Нет✅ Vulkan
Samsung Xclipse (RDNA2)❌ Нет✅ Vulkan
Intel Iris Xe (iGPU)❌ Нет✅ Vulkan
AMD Radeon 680M/780M (iGPU)❌ Нет✅ Vulkan
Vulkan — это спецификация низкоуровневого GPU API от Khronos Group (2016). Все основные производители GPU реализуют Vulkan в своих драйверах. Один и тот же код шейдера (GLSL → SPIR-V) работает на NVIDIA, AMD, Intel, ARM, Qualcomm — без изменений.

Почему именно Vulkan, а не ROCm/SYCL/OpenCL?

Ключевой факт: Vulkan бэкенд уже написан и протестирован в llama.cpp. Это ~15,000 строк C++ и ~30 GLSL-шейдеров. Prima.cpp — это форк llama.cpp. Значит, портирование — это не «написать Vulkan с нуля», а «подключить существующий код».

4. CUDA vs Vulkan — полный словарь перевода

4.1 Код бок о бок: mul_mat_vec (матрица × вектор)

Это ключевая операция при генерации каждого нового токена. Одна строка матрицы весов умножается на входной вектор. Вот как она выглядит в CUDA и Vulkan:

CUDA (текущий prima.cpp)

// Файл: ggml/src/ggml-cuda/mmv.cu
// Язык: CUDA C++ (.cu)
// Компилятор: nvcc → PTX → SASS
// Работает: только NVIDIA

__global__ void mul_mat_vec_q4_0(
    const void * __restrict__ src0,  // матрица Q4_0
    const float * __restrict__ src1,  // входной вектор
    float * __restrict__ dst,         // результат
    int ncols, int nrows)
{
    // Индексы: CUDA встроенные переменные
    const int row = blockIdx.x;
    const int tid = threadIdx.x;
    const int block_size = blockDim.x;
    
    float sum = 0.0f;
    
    for (int col = tid; col < ncols; col += block_size) {
        // Деквантизация: Q4_0 → float
        const int block_idx = col / QK4_0;
        const int quant_idx = col % QK4_0;
        const block_q4_0 * b = &((block_q4_0*)src0)
            [row * (ncols/QK4_0) + block_idx];
        
        const float d = __half2float(b->d);
        const int   q = (b->qs[quant_idx/2] >> 
                        (4*(quant_idx & 1))) & 0xF;
        const float val = d * ((float)q - 8.0f);
        
        // Скалярное произведение
        sum += val * src1[col];
    }
    
    // Warp-level редукция (NVIDIA warp = 32)
    sum = warpReduceSum(sum);
    
    // Записать результат
    if (tid == 0) dst[row] = sum;
}

    src0, src1, dst, ncols, nrows);

5. Алгоритм Halda — детальный анализ и модификации

Halda (Heterogeneity-Aware Layer-to-Device Allocation) — «мозг» prima.cpp. Это алгоритм, решающий NP-трудную задачу оптимального распределения слоёв нейросети по гетерогенным устройствам.

5.2 Математическая модель задержки токена

Halda минимизирует задержку генерации одного токена Ttoken, которая складывается из:

T_token = max_over_devices(T_compute[m] + T_kvcache[m] + T_disk[m]) + T_network где для каждого устройства m: T_compute[m] = L_gpu[m] × (FLOPs_layer / GPU_FLOPS[m]) ← GPU FLOPS нужен от Vulkan + L_cpu[m] × (FLOPs_layer / CPU_FLOPS[m]) T_kvcache[m] = L_gpu[m] × t_kvcpy_gpu[m] ← GPU copy time нужен от Vulkan + L_cpu[m] × t_kvcpy_cpu[m] T_disk[m] = max(0, layers_not_in_RAM[m]) × t_disk_read[m] T_network = Σ latency[m → m+1] (по кольцу PRP)

Переменные оптимизации:

ПеременнаяТипЗначениеЗависит от Vulkan?

latency[m→n]Float (ms)Сетевая задержка между узламиНет

5.3 ILP-оптимизация через HiGHS

Halda решает задачу целочисленного линейного программирования (ILP):

Минимизировать: T_token = max{T_compute[1] + T_kvcache[1] + T_disk[1], ..., T_compute[N] + ...} + T_network При ограничениях: Σ L_gpu[m] + Σ L_cpu[m] = L_total (все слои распределены) L_gpu[m] × layer_size ≤ VRAM_avail[m] ∀m (VRAM не превышена) L_cpu[m] × layer_size ≤ RAM_avail[m] ∀m (RAM не превышена) L_gpu[m] ≥ 0, L_cpu[m] ≥ 0 ∀m (неотрицательность) Решатель: HiGHS (open-source, state-of-the-art LP/MIP solver) Время решения: 10–12 мс на 4–32 устройства
ILP-солвер HiGHS вообще не знает о GPU бэкендах. Он получает числа (FLOPS, VRAM, latency) и находит оптимальное распределение. Для Vulkan-порта нужно только правильно замерить числа — алгоритм оптимизации не меняется ни на строку.

6.2 Передача тензоров: GPU→CPU→сеть→CPU→GPU

Устройство A (GPU Vulkan): [VRAM] ──vkMapMemory()──▶ [RAM] ──ZMQ send──▶ [Сеть TCP/Wi-Fi] Устройство B (GPU CUDA): [Сеть] ──ZMQ recv──▶ [RAM] ──cudaMemcpy(H2D)──▶ [VRAM] Ключевой факт: данные ВСЕГДА проходят через CPU RAM. Фаза 1: Сборка с Vulkan (2–4 часа)

Цель: prima.cpp компилируется с GGML_VULKAN=1 без ошибок.

1.1 Установка зависимостей

# Ubuntu / Debian:
sudo apt install libvulkan-dev vulkan-tools glslc

# Проверить установку:
vulkaninfo --summary
# Должно показать ваш GPU и версию Vulkan API

# Fedora:
sudo dnf install vulkan-headers vulkan-loader-devel glslc

# Arch:
sudo pacman -S vulkan-devel shaderc

# Android (Termux):
pkg install vulkan-headers vulkan-loader-android

1.2 Модификация Makefile

# Найти секцию GGML_CUDA и добавить по аналогии:

ifdef GGML_VULKAN
  GGML_CFLAGS  += -DGGML_USE_VULKAN
  GGML_LDFLAGS += -lvulkan
  GGML_OBJ     += ggml/src/ggml-vulkan/ggml-vulkan.o
  
  # Компиляция шейдеров
  VULKAN_SHADER_GEN = ggml/src/ggml-vulkan/vulkan-shaders/vulkan-shaders-gen
  $(VULKAN_SHADER_GEN): ggml/src/ggml-vulkan/vulkan-shaders/vulkan-shaders-gen.cpp
  	$(CXX) $(CXXFLAGS) -o $@ $<
  
  ggml/src/ggml-vulkan/ggml-vulkan.o: $(VULKAN_SHADER_GEN)
  	$(VULKAN_SHADER_GEN)  # Генерация SPIR-V шейдеров
  	$(CXX) $(CXXFLAGS) $(GGML_CFLAGS) -c ggml/src/ggml-vulkan/ggml-vulkan.cpp -o $@
endif

Или если используется CMake:

cmake -B build -DGGML_VULKAN=ON -DUSE_HIGHS=ON
cmake --build build -j$(nproc)
