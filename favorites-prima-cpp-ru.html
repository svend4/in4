⚡ Каждый фаворит × prima.cpp: что меняется?

🥇 Фаворит #1: Mac Mini M4 16 ГБ ($599) — Moltbot AI-агент

До prima.cpp:
Сервер для AI-агента (Moltbot/Clawdbot). Облачный API для тяжёлых моделей. Локально — Llama 8B на 15–20 tok/s. Один узел, не кластер.
С prima.cpp:
Может стать узлом в гетерогенном кластере. Metal GPU поддерживается. 16 ГБ RAM → Halda назначит 5–10 слоёв из 80 (для 70B). SSD 7 ГБ/с → хороший disk offloading.

Но: Metal в prima.cpp медленнее CUDA. Один Mac Mini M4 c 16 ГБ — слабое звено в кластере.
Вердикт prima.cpp: Вердикт НЕ меняется. Mac Mini M4 16 ГБ остаётся лучшим как агент-сервер. Как LLM-нода он слишком слаб — 16 ГБ RAM не даст существенного вклада в кластер. prima.cpp позволяет добавить его как «помощника», но не как основу.

🥇 Фаворит #2: Mac Mini M4 Pro 64 ГБ ($2 199) — лучший single-node Apple

До prima.cpp:
64 ГБ unified memory + 273 ГБ/с bandwidth. 70B Q4: ~4–5 tok/s. Единственный портативный одноузловой вариант для 70B.
С prima.cpp:
В одиночку — prima.cpp = llama.cpp (нет смысла в распределении). В кластере — prima.cpp через Metal, но медленнее чем нативный EXO с RDMA. Halda может решить использовать только M4 Pro и отключить слабые узлы.
Вердикт prima.cpp: Вердикт НЕ меняется. Для одного узла prima.cpp не нужна. Для Mac-кластера EXO с TB5 RDMA остаётся быстрее. M4 Pro 64 ГБ — по-прежнему король single-node для 70B.

🥇 Фаворит #3: RTX 3090 б/у ($800–900) — лучший $/VRAM

До prima.cpp:
24 ГБ VRAM, 936 ГБ/с bandwidth. 30B: ~20 tok/s. Потолок = 30B (24 ГБ VRAM). 70B — не помещается, точка.
С prima.cpp:
CUDA ✅ Полная поддержка! Десктоп с RTX 3090 (24 ГБ VRAM + 64 ГБ RAM) в кластере prima.cpp: 70B ТЕПЕРЬ ВОЗМОЖЕН. Halda даёт GPU 20–25 слоёв из 80, остальные — на CPU + disk offloading.

Добавь ещё один десктоп с RTX 3070 (8 ГБ) → 70B на ~2–4 tok/s вместо «невозможно».
Вердикт prima.cpp: ВЕРДИКТ МЕНЯЕТСЯ! 🔄 RTX 3090 из «лучшая GPU для 30B» превращается в «ядро кластера для 70B». prima.cpp снимает потолок 24 ГБ VRAM. В комбинации с любым вторым устройством (даже ноутбук или телефон) — 70B становится реальностью. Это самый драматичный сдвиг от prima.cpp.

🥇 Фаворит #4: Minisforum UM890 Pro ($479) — бюджетный mini-PC

До prima.cpp:
Ryzen 9 8945HS, 32 ГБ DDR5, RDNA3 iGPU. 8B: 10–15 tok/s. Потолок = 13B (32 ГБ RAM). 70B невозможно.
С prima.cpp:
AMD iGPU ❌ Только CPU-mode. Но 32 ГБ RAM + быстрый NVMe → отличный disk offloading.

2× UM890 Pro ($958): 64 ГБ RAM, 2 CPU. prima.cpp PRP → 70B Q4 (~40 ГБ) влезает в RAM! Прогноз: 70B на ~1.5–2.5 tok/s (CPU-only, но без disk offloading).

4× UM890 Pro ($1 916): 128 ГБ RAM → даже 405B через disk offloading.
Вердикт prima.cpp: ВЕРДИКТ МЕНЯЕТСЯ! 🔄 UM890 Pro из «бюджетный 8B-бокс» превращается в «строительный блок 70B-кластера». 2 штуки за $958 → 70B. 4 штуки за $1 916 → 405B (очень медленно, но возможно). AMD iGPU не работает в prima.cpp — жаль, но CPU-only PRP всё равно открывает 70B.

🥇 Фаворит #5: 4× Mac Mini M4 Pro 64 ГБ + EXO + TB5 (~$8 800)

До prima.cpp:
256 ГБ unified memory. TB5 RDMA tensor parallelism через EXO. 70B: ~32 tok/s. Абсолютный чемпион по скорости среди домашних кластеров.
С prima.cpp:
prima.cpp использует pipeline (PRP), не tensor parallelism. На TB5 RDMA — EXO с TP значительно быстрее. prima.cpp на этом кластере: ~10–15 tok/s на 70B (pipeline overhead). EXO: ~32 tok/s.

prima.cpp полезна только если нужно запустить модель больше 256 ГБ (405B Q8, 671B) — тогда disk offloading через mmap даёт преимущество.
Вердикт prima.cpp: Вердикт НЕ меняется. Mac-кластер + EXO + TB5 RDMA остаётся непобедимым для моделей ≤256 ГБ. prima.cpp медленнее из-за pipeline вместо tensor parallelism. Единственный случай, когда prima.cpp выигрывает: модели >256 ГБ (нужен disk offloading). EXO — по-прежнему король Mac-кластеров.

🥇 Фаворит #6: 2× NVIDIA DGX Spark (~$6 000)

До prima.cpp:
256 ГБ unified memory. Blackwell GPU + 6144 CUDA cores. ConnectX-7 200 Гбит/с RDMA. 70B: ~8–15 tok/s. 405B: возможно на 2 узлах.
С prima.cpp:
CUDA ✅ ConnectX-7 ✅ DGX Spark — идеальное железо для prima.cpp. 128 ГБ unified + Blackwell GPU на каждом узле. Halda может оптимально распределить GPU и CPU слои.

Но: DGX Spark уже имеет собственный RDMA-стек и NVIDIA-оптимизированный инференс. prima.cpp может быть медленнее нативных инструментов NVIDIA (vLLM, TensorRT-LLM).
Вердикт prima.cpp: Вердикт ЧАСТИЧНО меняется. DGX Spark + prima.cpp = отличная комбинация для гетерогенных кластеров (DGX + старый ноутбук + телефон). Но для чистого DGX-кластера — NVIDIA-нативный стек быстрее. prima.cpp добавляет ценность, если DGX Spark — самый мощный узел в смешанном кластере.

🥇 Фаворит #7: Framework Desktop 128 ГБ ($1 999) — лучший $/bandwidth ПК

До prima.cpp:
Strix Halo, 256 ГБ/с, 128 ГБ LPDDR5X. 70B Q4: ~4–5 tok/s (один узел). Кластер через llama.cpp RPC: ~0.7 tok/s (хуже одного узла из-за TCP overhead).
С prima.cpp:
AMD iGPU ❌ Только CPU. Один узел: prima.cpp = llama.cpp, нет преимущества.

2× Framework Desktop ($3 998): 256 ГБ RAM → 405B Q4 (~230 ГБ) ВПЕРВЫЕ ВОЗМОЖЕН! prima.cpp PRP + disk offloading. Прогноз: 405B на ~0.5–1.5 tok/s (CPU-only).

Сравнение: llama.cpp RPC на 2 узлах → ~0.3 tok/s (pipeline overhead). prima.cpp → ~0.5–1.5 tok/s (PRP + prefetching). 2–5× ускорение!
Вердикт prima.cpp: ВЕРДИКТ МЕНЯЕТСЯ! 🔄 Framework Desktop из «лучший single-node, но бесполезен в кластере» превращается в «строительный блок для 405B/671B». prima.cpp — единственный фреймворк, который делает кластер из Framework Desktop быстрее одного узла на больших моделях. Без Vulkan — потенциал раскрыт не полностью (AMD iGPU спит).

🥇 Фаворит #8: Minisforum MS-S1 Max ($2 299) — лучший для кластеризации

До prima.cpp:
Strix Halo 128 ГБ, dual 10 GbE, USB4v2. Идеальный сетевой стек для кластера. Но llama.cpp RPC через TCP: кластер медленнее одного узла. Вердикт: «великолепное железо, ждём софт».
С prima.cpp:
AMD iGPU ❌ Только CPU. Но dual 10 GbE = наиболее быстрый интерконнект для prima.cpp среди мини-ПК.

4× MS-S1 Max ($9 196): 512 ГБ RAM, dual 10 GbE кольцо, PCIe 5.0 NVMe 10+ ГБ/с.
• 70B Q4: RAM хватает на 1 узел → prima.cpp использует только 1 → нет преимущества
• 405B Q4 (~230 ГБ): 2 узла → ~0.5–1.5 tok/s
• DeepSeek V3 671B Q4 (~380 ГБ): 3 узла → ~0.2–0.5 tok/s
• Llama 3 405B Q8 (~400 ГБ): 4 узла → ~0.2–0.5 tok/s
Вердикт prima.cpp: ВЕРДИКТ МЕНЯЕТСЯ! 🔄 MS-S1 Max из «железо будущего в ожидании софта» превращается в «единственную мини-ПК платформу для DeepSeek V3 671B дома». prima.cpp — тот самый софт, которого не хватало. Dual 10 GbE раскрывается для PRP кольца. Жаль, что без Vulkan AMD iGPU (59.4 ТФЛОПС!) спит.

🥇 Фаворит #9: 4× Orange Pi 5 Plus 16 ГБ (~$600) — лучший SBC-кластер

До prima.cpp:
RK3588, 64 ГБ суммарно, Gigabit Ethernet. distributed-llama: 8B на 6–13 tok/s. 70B: невозможно (RAM <40 ГБ свободных + нет disk offloading).
С prima.cpp:
GPU ❌ ARM CPU only. Но: mmap disk offloading + PRP! 70B Q4 ТЕПЕРЬ ВОЗМОЖЕН даже на 64 ГБ кластере!

Halda профилирует каждый RK3588: слабый CPU (~4 TOPS), NVMe 1–2 ГБ/с, 16 ГБ RAM.
• PRP с k=4 оборота → prefetching перекрывает disk I/O
• Прогноз 70B: ~2000–3000 мс/токен (0.3–0.5 tok/s)
• Прогноз 32B: ~300–500 мс/токен (2–3.3 tok/s)

Сравнение: distributed-llama → 70B: OOM. llama.cpp на 1 узле → 70B: 30+ сек/токен. prima.cpp: 2–3 сек/токен. Из «невозможно» в «медленно, но можно».
Вердикт prima.cpp: ВЕРДИКТ МЕНЯЕТСЯ! 🔄 Orange Pi 5 Plus кластер из «только для 8B моделей» превращается в «самый дешёвый способ запустить 70B дома — за $600». Да, 0.3–0.5 tok/s — это медленно. Но это не ноль. Для batch-генерации, фоновых задач, overnight reasoning — работает. Революция для ультрабюджета.

🥇 Фаворит #10: 4× Raspberry Pi 5 8 ГБ (~$585) — самый протестированный

До prima.cpp:
32 ГБ суммарно. Gigabit Ethernet. distributed-llama: 8B на ~6–13 tok/s. Jeff Geerling: «Я жалею, что построил этот кластер».
С prima.cpp:
GPU ❌ ARM CPU only. 32 ГБ суммарно — МЕНЬШЕ чем 70B Q4 (~40 ГБ) → нужен интенсивный disk offloading.

• 70B: mmap с microSD/USB SSD (0.1–0.4 ГБ/с) → disk bottleneck критичен
• Прогноз 70B: ~5000–15000 мс/токен (0.07–0.2 tok/s)
• С NVMe HAT (2+ ГБ/с): ~3000–5000 мс/токен (0.2–0.33 tok/s)
• 32B: ~500–1000 мс/токен (1–2 tok/s) — терпимо!
Вердикт prima.cpp: Вердикт ЧАСТИЧНО меняется. Pi 5 кластер с prima.cpp технически может запустить 70B, но 0.07–0.2 tok/s — это 5–15 секунд на токен. Непрактично для интерактивного использования. Для 32B моделей (QwQ-32B, Qwen 2.5-32B) — 1–2 tok/s уже реалистичнее. Jeff Geerling по-прежнему жалел бы, но чуть меньше. Orange Pi 5 Plus с 16 ГБ RAM и NVMe — значительно лучший выбор для prima.cpp.

🏆 НОВЫЙ ФАВОРИТ: Гетерогенный кластер с NVIDIA GPU

⚡ Фаворит #11 (НОВЫЙ): Гетерогенный кластер для prima.cpp

prima.cpp создаёт совершенно новую категорию, которой не было ни в одной из 6 частей серии: кластер из «того, что есть дома» + одна покупка NVIDIA GPU.

Почему это новый фаворит:

• $1 280 — дешевле Mac Mini M4 Pro ($2 199)
• 70B на 1.4–2.5 tok/s — медленнее Mac Mini M4 Pro (4–5 tok/s), но 70B вместо потолка 30B у RTX 3090
• Используй то, что есть — старый ноутбук и телефон бесплатно добавляют мощности
• Масштабируемость: купил друг RTX 4060 → подключай к кластеру, Halda перераспределит

🎯 Абсолютный вердикт серии

prima.cpp меняет вердикт для 5 из 10 фаворитов

Где prima.cpp бесполезна (вердикт не меняется):

• Одиночные мощные узлы (Mac Mini M4 Pro 64 ГБ, Framework Desktop 128 ГБ) — если модель влезает в RAM одного устройства, prima.cpp не нужна.
• Однородные Mac-кластеры (4× Mac Mini + EXO + TB5 RDMA) — tensor parallelism + RDMA непобедимы. prima.cpp медленнее.

Где prima.cpp — революция (вердикт кардинально меняется):

• RTX 3090 + «что есть дома» → 70B из «невозможно» в 1.5–2.5 tok/s за $800–1 300
• 2× бюджетных мини-ПК → 70B из «невозможно» в 1.5–2.5 tok/s за $958
• ПК-кластеры Strix Halo → 405B/671B из «невозможно» в 0.2–1.5 tok/s
• SBC Orange Pi 5 Plus → 70B из «невозможно» в 0.3–0.5 tok/s за $600
• Гетерогенные «свалки» → любая комбинация устройств впервые работает вместе
