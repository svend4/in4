2. llama.cpp server: полная настройка

Сборка

# Клонировать и собрать: git clone https://github.com/ggerganov/llama.cpp.git cd llama.cpp && mkdir build && cd build # CPU only: cmake .. && cmake --build . --config Release -j$(nproc) # С CUDA: cmake .. -DGGML_CUDA=ON && cmake --build . --config Release -j$(nproc) # С Vulkan: cmake .. -DGGML_VULKAN=ON && cmake --build . --config Release -j$(nproc) # С Metal (macOS): cmake .. -DGGML_METAL=ON && cmake --build . --config Release -j$(nproc)

Запуск сервера

# Базовый запуск: ./llama-server \ --model /models/llama-3.3-70b-Q4_K_M.gguf \ --host 0.0.0.0 \ --port 8080 \ --n-gpu-layers 99 \ --threads 10 \ --ctx-size 8192 \ --parallel 4 \ --batch-size 2048 \ --flash-attn \ --cache-type-k q8_0 \ --cache-type-v q8_0 \ --mlock # Ключевые параметры: # --parallel N : обслуживать N одновременных запросов # --ctx-size N : контекст (делится между parallel слотами!) # Реальный ctx на клиента = ctx-size / parallel # --cont-batching : непрерывный батчинг (по умолчанию вкл.) # --metrics : экспорт Prometheus метрик на /metrics

Firewall (ufw)

# Базовая настройка: sudo ufw default deny incoming sudo ufw default allow outgoing # Разрешить SSH: sudo ufw allow ssh # Разрешить LLM API только из локальной сети: sudo ufw allow from 192.168.1.0/24 to any port 8080 # Разрешить мониторинг из локальной сети: sudo ufw allow from 192.168.1.0/24 to any port 3000 # Grafana sudo ufw allow from 192.168.1.0/24 to any port 9090 # Prometheus # Кластерный трафик (prima.cpp workers): sudo ufw allow from 192.168.1.0/24 to any port 8888 # Включить: sudo ufw enable sudo ufw status verbose

# Установка: sudo apt install -y wireguard # Генерация ключей (на сервере): wg genkey | tee /etc/wireguard/server_private.key | wg pubkey > /etc/wireguard/server_public.key # /etc/wireguard/wg0.conf (сервер): [Interface] Address = 10.200.0.1/24 ListenPort = 51820 PrivateKey = SERVER_PRIVATE_KEY [Peer] PublicKey = CLIENT_PUBLIC_KEY AllowedIPs = 10.200.0.2/32 # Запуск: sudo systemctl enable wg-quick@wg0 sudo systemctl start wg-quick@wg0 sudo ufw allow 51820/udp # Теперь LLM API доступен через VPN: http://10.200.0.1:8080

API аутентификация

# llama.cpp server поддерживает --api-key: ./llama-server --model model.gguf --api-key "your-secret-key-here" # Клиент: curl http://localhost:8080/v1/chat/completions \ -H "Authorization: Bearer your-secret-key-here" \ -d '{"model":"llama","messages":[{"role":"user","content":"Hi"}]}' # NGINX rate limiting (/etc/nginx/conf.d/llm.conf): limit_req_zone $binary_remote_addr zone=llm:10m rate=10r/s; server { listen 443 ssl; server_name ai.example.com; ssl_certificate /etc/letsencrypt/live/ai.example.com/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/ai.example.com/privkey.pem; location /v1/ { limit_req zone=llm burst=20 nodelay; proxy_pass http://127.0.0.1:8080; proxy_set_header Host $host; proxy_read_timeout 300s; } }
Никогда не делайте:
- Не открывайте порт 8080 в интернет без аутентификации
- Не запускайте LLM-сервер от root
- Не используйте пустой --api-key
- Не отключайте файрвол «для удобства»

12. Типичные проблемы 24/7 работы

Проблема Симптомы Решение
OOM Killer Процесс внезапно убит. dmesg | grep oom Установить MemoryMax= в systemd. Использовать --mlock. Уменьшить ctx-size
Memory leak RAM медленно растёт, через дни — OOM Автоматический перезапуск по расписанию: systemctl restart llama-server через timer
GPU memory frag CUDA out of memory при достаточном VRAM Перезапуск процесса. Установить CUDA_LAUNCH_BLOCKING=1 для отладки
NVMe износ S.M.A.R.T. предупреждения Мониторить smartctl -a /dev/nvme0. Типичный TBW: 600 ТБ для 1 ТБ SSD. При mmap: ~10 ТБ/мес → 5 лет
Диск заполнен Логи, кеш моделей, core dumps Logrotate для журналов. journalctl --vacuum-size=500M. Cron для очистки
Сеть отвалилась Worker недоступен, prima.cpp зависает NetworkManager + auto-reconnect. Systemd Restart=on-failure. Health check скрипт
Thermal throttling tok/s падает через 30–60 мин Мониторить температуру. Улучшить охлаждение. Ограничить TDP в BIOS

Скрипт health check

#!/bin/bash # /opt/scripts/health-check.sh # Запускать через cron каждые 5 минут ENDPOINT="http://localhost:8080/health" RESPONSE=$(curl -s -o /dev/null -w "%{http_code}" --max-time 10 "$ENDPOINT") if [ "$RESPONSE" != "200" ]; then echo "$(date): LLM server unhealthy (HTTP $RESPONSE), restarting..." systemctl restart llama-server # Опционально: отправить в Telegram curl -s "https://api.telegram.org/bot$TOKEN/sendMessage" \ -d "chat_id=$CHAT_ID" \ -d "text=LLM server restarted at $(date)" fi
# Crontab: # crontab -e */5 * * * * /opt/scripts/health-check.sh >> /var/log/health-check.log 2>&1 # Автоматический перезапуск раз в неделю (для memory leaks): 0 4 * * 0 systemctl restart llama-server

13. Калькулятор TCO (Total Cost of Ownership)

Формула годового TCO

TCO_год = (Hardware / Срок_амортизации) + Электричество_год + Обслуживание_год Где: Электричество_год = Мощность_Вт × 24 × 365 / 1000 × Тариф_$/кВт·ч Обслуживание ≈ 2–4 часа/месяц × ваша_часовая_ставка (или $0 для хобби)
