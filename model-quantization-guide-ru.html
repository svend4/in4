2. Dense vs MoE: что выбрать для домашнего кластера

Dense модели

Все параметры активны на каждом токене.

- RAM = пропорционально общим параметрам
- Bandwidth = пропорционально общим параметрам
- Качество = предсказуемое, стабильное
- Пример: Llama 70B — 70B параметров, все используются

Формула скорости:
tok/s ≈ bandwidth / model_size

MoE модели

Только часть параметров активна на каждом токене (эксперты).

- RAM = пропорционально ОБЩИМ параметрам (все эксперты в памяти)
- Bandwidth = пропорционально АКТИВНЫМ параметрам (только выбранные эксперты)
- Качество = на уровне dense модели с активными параметрами
- Пример: Qwen3-30B-A3B — 30B общих, но только 3B активны

Формула скорости:
tok/s ≈ bandwidth / active_size

Почему MoE — идеальны для SBC и мини-ПК:
Qwen3-30B-A3B: 30B параметров → ~5.5 ГБ в Q4_0 → влезает на 4× Pi 5 (8 ГБ каждый).
Но качество ≈ dense 3B модели (или даже лучше — больше «знаний» за счёт 30B общих параметров).
Скорость определяется 3B активных параметров → 13 tok/s на Pi-кластере!
Dense модель 3B влезла бы на один Pi 5, но MoE 30B-A3B умнее при той же скорости.

3. Квантизация: полный справочник GGUF

4. Формулы расчёта памяти

Общая формула: RAM_total = RAM_model + RAM_kv_cache + RAM_overhead RAM_model (модель): RAM_model = parameters × bits_per_weight / 8 Пример: Llama 70B Q4_K_M = 70×10⁹ × 4.8 / 8 = 42 ГБ RAM_kv_cache (KV-кеш для контекста): RAM_kv = 2 × n_layers × n_kv_heads × head_dim × context_len × bytes_per_elem Llama 70B: 2 × 80 × 8 × 128 × 4096 × 2 (FP16) = 1.34 ГБ (при ctx=4096) Llama 70B: 2 × 80 × 8 × 128 × 32768 × 2 (FP16) = 10.7 ГБ (при ctx=32K) С KV cache Q8_0 квантизацией: ÷2 (0.67 ГБ при ctx=4096) С KV cache Q4_0 квантизацией: ÷4 (0.34 ГБ при ctx=4096) RAM_overhead: ~500 МБ – 2 ГБ (зависит от бэкенда, batch size, буферы) Итого для Llama 70B Q4_K_M, ctx=4096: 42 + 1.34 + 1.0 ≈ 44.3 ГБ

6. Скорость инференса: формулы и расчёты

Два режима работы LLM

Prefill (обработка промпта)

Compute-bound — ограничен FLOPS процессора.

Время = 2 × params × tokens / FLOPS

Llama 70B, 1000 токенов промпта, M4 Pro (4.5 TFLOPS FP16):
2 × 70×10⁹ × 1000 / 4.5×10¹² = 31 сек

На GPU RTX 4090 (82 TFLOPS FP16):
2 × 70×10⁹ × 1000 / 82×10¹² = 1.7 сек

Decode (генерация токенов)

Memory-bandwidth-bound — ограничен пропускной способностью памяти.

Теор. tok/s = bandwidth / model_size

Llama 70B Q4_K_M (42 ГБ), M4 Pro (273 ГБ/с):
273 / 42 = 6.5 tok/s (теоретический макс.)
Реально: ~4–5 tok/s (60–75% от теоретического)

Framework Desktop Strix Halo (256 ГБ/с):
256 / 42 = 6.1 tok/s → реально ~4–5 tok/s

7. Speculative Decoding

Speculative decoding — техника ускорения инференса в 2–3×. Маленькая «draft» модель быстро генерирует N кандидатов-токенов, а большая «target» модель проверяет их за один проход.

Без speculative decoding (70B): Token 1: [compute 150ms] → Token 2: [compute 150ms] → ... Итого: 150 мс/токен = 6.7 tok/s С speculative decoding (draft=1B, target=70B, N=5): Draft: [generate 5 tokens: 5ms] Target: [verify 5 tokens in 1 pass: ~180ms] Если 3 из 5 приняты: 180ms / 3 = 60 мс/токен = 16.7 tok/s Ускорение: 2.5× Acceptance rate зависит от: - Качество draft модели (чем ближе к target — тем лучше) - Сложность текста (простой текст = высокий acceptance) - Типичный acceptance rate: 50–80%

Настройка в llama.cpp

# Скачать draft модель (та же семья, но маленькая): # Для Llama 70B → draft = Llama 3.2 1B # Для QwQ-32B → draft = Qwen 2.5 1.5B # Запуск с speculative decoding: ./llama-speculative \ --model llama-3.3-70b-Q4_K_M.gguf \ --model-draft llama-3.2-1b-Q8_0.gguf \ --n-gpu-layers 99 \ --n-gpu-layers-draft 99 \ --draft-max 8 \ --draft-min 2 \ --prompt "Explain quantum computing" # Параметры: # --draft-max N: максимум N токенов за одну спекуляцию (5–10) # --draft-min N: минимум N токенов (2–3) # --draft-p-min: мин. вероятность для принятия (0.5–0.9)

Настройка в prima.cpp

# prima.cpp поддерживает speculative decoding распределённо: # Draft модель — на самом быстром GPU # Target модель — распределена по кластеру ./prima-cli \ --model llama-3.3-70b-Q4_K_M.gguf \ --model-draft llama-3.2-1b-Q8_0.gguf \ --workers 192.168.1.101:8888,192.168.1.102:8888 \ --n-predict 256 # Результат из статьи: QwQ-32B + spec. decoding = 26 tok/s!
Когда speculative decoding помогает:
- Модели 30B+ (compute-heavy → много выигрыша от batch verification)
- GPU с высоким FLOPS (RTX 4090 — batch verify 8 токенов почти бесплатно)
- Простые задачи (перевод, суммаризация — высокий acceptance rate)

Когда НЕ помогает:
- Модели <14B (уже быстрые, overhead от draft не оправдан)
- CPU-only (нет batch processing ускорения)
- Сложные reasoning задачи (низкий acceptance rate)

8. KV Cache оптимизация

KV Cache хранит Key и Value тензоры для всех предыдущих токенов — позволяет не пересчитывать attention для всего контекста при каждом токене.

Размер KV Cache для популярных моделей

Llama 8B328 (GQA)1280.25 ГБ2.0 ГБ8.0 ГБ
QwQ-32B648 (GQA)1280.5 ГБ4.0 ГБ16 ГБ
Llama 70B808 (GQA)1281.3 ГБ10.7 ГБ42 ГБ
Llama 405B1268 (GQA)1282.1 ГБ16.5 ГБ66 ГБ
KV cache на длинных контекстах ОГРОМЕН! Llama 70B при контексте 128K: KV cache = 42 ГБ — столько же, сколько сама модель! На практике контекст 4–8K достаточен для 90% задач.

KV Cache квантизация

# llama.cpp поддерживает квантизацию KV cache: ./llama-cli \ --model model.gguf \ --cache-type-k q8_0 \ --cache-type-v q8_0 \ --ctx-size 8192 # Q8_0 KV: потеря качества минимальна, экономия 50% RAM # Q4_0 KV: заметная потеря на длинных контекстах, экономия 75% # Flash Attention (экономия памяти + ускорение): ./llama-cli \ --model model.gguf \ --flash-attn \ --ctx-size 8192
Рекомендация: Всегда используйте --cache-type-k q8_0 --cache-type-v q8_0 для экономии RAM. Потеря качества незаметна, а экономия 50% KV cache позволяет увеличить контекст в 2× или освободить RAM для большей модели.

12. Инструменты: скачивание, конвертация, бенчмарки

Скачивание моделей

# Способ 1: huggingface-cli (рекомендуется) pip install huggingface_hub huggingface-cli download \ bartowski/Llama-3.3-70B-Instruct-GGUF \ Llama-3.3-70B-Instruct-Q4_K_M.gguf \ --local-dir ./models # Способ 2: wget напрямую wget https://huggingface.co/bartowski/Llama-3.3-70B-Instruct-GGUF/resolve/main/Llama-3.3-70B-Instruct-Q4_K_M.gguf # Способ 3: Ollama (автоматически скачивает) ollama pull llama3.3:70b-instruct-q4_K_M # Лучшие источники GGUF: # - bartowski (HuggingFace) — лучшие квантизации, importance matrix # - TheBloke — классический источник (менее активен) # - Official repos (Meta, Qwen) — оригинальные веса

Квантизация своими руками

# Если нужна нестандартная квантизация: # 1. Скачать модель в safetensors/pytorch формате huggingface-cli download meta-llama/Llama-3.3-70B-Instruct --local-dir ./llama-70b # 2. Конвертировать в GGUF (FP16): cd llama.cpp python convert_hf_to_gguf.py ./llama-70b --outfile llama-70b-f16.gguf # 3. Квантизовать: ./llama-quantize llama-70b-f16.gguf llama-70b-Q4_K_M.gguf Q4_K_M # Доступные типы квантизации: # Q8_0, Q6_K, Q5_K_M, Q5_K_S, Q4_K_M, Q4_K_S, Q4_0, # Q3_K_M, Q3_K_S, Q2_K, IQ4_XS, IQ3_XXS, IQ2_XXS, IQ1_S # С importance matrix (лучшее качество при агрессивной квантизации): ./llama-quantize --imatrix imatrix.dat \ llama-70b-f16.gguf llama-70b-IQ4_XS.gguf IQ4_XS

Бенчмарки

# llama-bench — встроенный бенчмарк: ./llama-bench \ --model llama-70b-Q4_K_M.gguf \ -ngl 99 \ -t 10 \ --batch-size 512 \ --n-prompt 512 \ --n-gen 128 # Выводит: prompt tok/s, generation tok/s, memory usage # Perplexity (измерение качества): ./llama-perplexity \ --model llama-70b-Q4_K_M.gguf \ --file wiki.test.raw \ --ctx-size 512 \ --batch-size 512 # Ожидание для Llama 70B: # F16: PPL = 3.31 # Q8_0: PPL = 3.32 (+0.3%) # Q6_K: PPL = 3.33 (+0.6%) # Q4_K_M: PPL = 3.37 (+1.8%) # Q3_K_M: PPL = 3.46 (+4.5%) # IQ2_XXS: PPL = 3.72 (+12.4%)
